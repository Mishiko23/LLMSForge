# LLMS Forge — MODX 3

Бесплатное дополнение для MODX 3. Лицензия: GNU GPL v3, полный текст в `COPYING`.

## Версия 0.5.0 — проверка установки

В админке появилась кнопка «Проверить»: показывает регистрацию маршрута, журнала, включение публикации в выбранном контексте, корректность адреса сайта и возможность записи статистики. Проверки относятся к конфигурации MODX; они не подтверждают, что веб-сервер перенаправляет `/llms.txt` в MODX. После обновления проверьте публичный URL вручную. Для сайтов с Apache/nginx может потребоваться уже использованное вами правило перенаправления.

Архив с `core`/`assets` предназначен для ручного обновления. Transport-пакет собирается скриптом `_build/build.transport.php` на установленном MODX 3. Перед публикацией нужно проверить установку, обновление, удаление, права доступа, несколько контекстов и настройки веб-сервера на тестовом сайте.

## Обновление 0.4.0 — журнал AI-ботов

После замены core/assets обязательно повторно запустите setup.php: он регистрирует плагин LLMSForgeVisits на OnHandleRequest. Журнал начинает собираться с момента установки; история из access.log не импортируется. Для остановки сбора отключите LLMSForgeVisits в MODX.

В админке нажмите «Обновить журнал»: периоды 1/7/30 календарных дней UTC, фильтр по точному имени бота, счётчики запросов/успешных ответов и последние 200 обращений с адресом, временем UTC, методом GET/HEAD и статусом. HEAD не означает загрузку тела страницы. Бот определяется только по User-Agent, который может быть подделан; проверки IP нет. Поддерживаются GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-SearchBot, Claude-User, PerplexityBot, Perplexity-User и общие краулеры Applebot, Amazonbot, Bytespider (их обращения не обязательно связаны с AI).

Учитываются обычные страницы и маршруты LLMS, прошедшие через MODX, в том числе неуспешные запросы. Статика, ответы CDN/веб-сервера и запросы авторизованных администраторов не учитываются. Это обращения, а не доказательство чтения, обучения или цитирования.

Записи хранятся в core/components/llmsforge/var/visits с PHP-защитой, без IP, полного User-Agent, query string и cookies. PHP должен иметь право создавать эту папку. Лимит — 5 МБ на день для всех контекстов, при достижении новые события этого дня пропускаются. Файлы старше 30 дней удаляются при следующей записи; при отсутствии трафика остаются до следующего события. Отчёт показывает только последние 30 дней. При обновлении не удаляйте папку var. Ошибки аналитики не прерывают выдачу страниц; отсутствие записей также может означать отсутствие прав записи.

Проверки: php tests/visits.php. Интеграцию на реальном MODX следует проверить запросом с тестовым User-Agent, например curl -A GPTBot/1.0 https://your-site/llms.txt. Такая запись является тестовой, не реальным визитом OpenAI.

## Обновление 0.3.1

Добавлены счётчики состава текущих настроек: загруженные в таблицу ресурсы, выбранные и исключённые ID, карточки по источникам и UTF-8 размер основного файла после предпросмотра. Это не журнал посещений и не число обращений AI-ботов. При редактировании размер сбрасывается до нового предпросмотра.

Массовые действия: выбрать все найденные, добавить опубликованные, снять выбор найденных, инвертировать найденные, очистить весь выбор. Поиск ограничивает область действий, ранее выбранные ID вне поиска сохраняются. Лимит 1000 ID проверяется до применения массового действия. Таблица ограничена 2000 загруженными ресурсами; это не полный счётчик сайта.

Совместимость: обычные документы и классы ресурсов на базе modResource используют общие поля pagetitle, description, content. Товары и категории miniShop3 поддерживаются на уровне этих полей, без цен, остатков и характеристик. WebLink/SymLink не разворачиваются в целевую страницу; StaticResource не читает файл вместо content. Содержимое TV, динамических сниппетов и сторонних таблиц не извлекается. Для таких страниц используйте ручные карточки Markdown.

Обновление: заменить файлы core/assets, повторно запустить setup.php, обновить админку. Существующие настройки сохраняются. Правила .htaccess остаются прежними.

LLMS Forge — генератор llms.txt для MODX 3. Редактор основного файла, карточки Markdown и интерфейс администратора. Требует PHP 8.1+.

## Новое в 0.3.0

- Основной llms.txt: автоматическая сборка или ручной Markdown.
- Кнопка «Добавить LLMS для страницы»: название, URL страницы, адрес Markdown, раздел, источник данных.
- Карточки с ручным текстом или актуальным содержимым ресурса MODX. Подходят для страниц, статей и ресурсов товаров/категорий. Специальные поля miniShop3 (цены, остатки, характеристики) пока не извлекаются.
- Предпросмотр отдельной карточки и основного файла; скачивание TXT/MD.
- Публикация адресов `/llms.txt` и `/llms-txt/имя-карточки` плагином OnPageNotFound. Физические файлы на диске не создаются.
- Ссылки на карточки автоматически добавляются в основной документ. Для автоматических карточек проверяются ресурс, предки, публикация, сроки и группы доступа.

Для обновления замените файлы `core` и `assets`, запустите `/assets/components/llmsforge/setup.php` и нажмите «Установить / обновить модуль». Затем обновите админку, заполните название сайта, выберите режим, добавьте карточки, включите публикацию и сохраните. Удалите setup.php после установки.

Для публичных адресов нужны Friendly URLs и перенаправление неизвестных путей в MODX. При нескольких доменах должен быть настроен выбор контекста. Существующие файлы/ресурсы по тем же адресам имеют приоритет: установщик их не заменяет. Выключение публикации отключает только маршруты плагина; существующий ресурс со сниппетом нужно снять с публикации отдельно.

Ручные карточки являются отдельными публичными материалами администратора: удаление или закрытие исходной страницы не удаляет такой текст. Для автоматической проверки доступности используйте источник «Ресурс MODX». HTML и теги MODX из автоматического текста очищаются; сниппеты не выполняются. Динамическое содержимое шаблона и TV автоматически не экспортируются.

Пределы этой версии: 200 карточек, до 50 КБ Markdown на карточку, до 60 КБ на все карточки вместе с метаданными; основной Markdown — до 60 КБ.

## Интерфейс администратора

После установки пакета откройте **Компоненты → LLMS Forge**. Требуется разрешение MODX `settings`.

- Выберите контекст сайта. Настройки сохраняются как настройки выбранного контекста.
- Укажите название и описание, найдите страницы в таблице и отметьте их флажками.
- Названия разделов можно вводить напротив страниц. Порядок ссылок регулируется полем ID; отдельное поле позволяет исключить страницы.
- Нажмите «Предпросмотр»: документ формируется на сервере из текущих полей без сохранения. Его можно скачать.
- Выберите доступность «Опубликовать при сохранении» и нажмите «Сохранить настройки». При отсутствии конфликтующего ресурса адрес llms.txt начнёт обслуживаться плагином. Ресурс со сниппетом остаётся альтернативным способом подключения.

При переключении контекста и выходе из страницы показывается предупреждение о несохранённых изменениях. Сохранение защищено проверками сессии, разрешения и CSRF-токена. В таблице показано до 2000 ресурсов; остальные можно добавить по ID. Интерфейс пока на русском языке.

## Реализовано

- Markdown: название, описание, разделы, ссылки и описания страниц.
- Явный список ресурсов с сохранением порядка, исключения и удаление дубликатов URL.
- Работа в текущем контексте, настройки могут переопределяться в контексте.
- Исключение удалённых, неопубликованных, недоступных, не участвующих в поиске и всех сгруппированных ресурсов. Проверяются даты публикации и снятия с публикации.
- Очистка HTML и тегов MODX без выполнения сниппетов; экранирование Markdown.
- Сниппет и скрипт сборки transport-пакета. Существующие настройки при обновлении сохраняются.

## Установка для разработки

### Быстрая установка после загрузки файлов на сервер

1. Загрузите папки `core` и `assets` из архива в корень MODX с объединением каталогов. Если каталог core перенесён, файлы `core/components/llmsforge` должны попасть в фактический MODX_CORE_PATH.
2. Войдите в админку MODX с правом `settings`.
3. На том же домене откройте `/assets/components/llmsforge/setup.php` (добавьте путь установки MODX, если сайт находится в подкаталоге).
4. Нажмите «Установить / обновить модуль». Установщик зарегистрирует namespace, меню, сниппет и отсутствующие системные настройки.
5. Обновите страницу админки. Откройте **Компоненты → LLMS Forge** и удалите setup.php с сервера.

Это ручная установка: она не добавляет запись в список transport-пакетов. Для распространения через менеджер пакетов используйте сборку ниже. Повторный запуск сохраняет системные и контекстные настройки, но обновляет код сниппета LLMSForge.

### Сборка transport-пакета

1. Скопировать `core/components/llmsforge` и `assets/components/llmsforge` в соответствующие каталоги сайта.
2. Выполнить `php _build/build.transport.php /path/to/modx/config.core.php` из исходников. Пакет появится в `core/packages` указанной установки MODX.
3. Установить пакет через менеджер пакетов.
4. Задать системную настройку `llmsforge.title` и при необходимости `llmsforge.description`.
5. В `llmsforge.include_ids` указать ID выбранных страниц через запятую, например `1,12,15`. Пустой список не экспортирует страницы. Максимум — 1000 ID.
6. `llmsforge.exclude_ids` — исключения. `llmsforge.sections` — JSON вида `{"1":"О компании","12":"Документация"}`.
7. Создать ресурс с пустым шаблоном и содержимым `[[!LLMSForge]]`. Установить тип содержимого `text/plain`, отключить кеширование и участие в поиске. Настроить URI `llms.txt` через переопределение URI. Не добавлять этот ресурс в список экспорта.
8. Опубликовать ресурс и проверить `/llms.txt` в анонимном браузере. Для каждого контекста создать свой ресурс и настройки. Friendly URLs должны быть настроены на сайте.

Документ генерируется при запросе, поэтому не требует записи файла в корень сайта. Статический файл llms.txt, если он уже существует, может перехватывать запрос — его судьбу нужно решить отдельно. Страница llms.txt должна быть публичной. Не использовать полноэкранный HTML-шаблон.

## Проверки

`php tests/renderer.php` проверяет формат, дубликаты, небезопасные схемы URL, экранирование и очистку контента.

`php tests/manager.php` проверяет валидацию настроек, порядок ID и отбрасывание некорректных значений. `node --check assets/components/llmsforge/mgr.js` проверяет синтаксис интерфейса.

`php tests/documents.php` проверяет карточки, очистку контента, источники, ограничения доступа и даты. `node tests/interface.cjs` (требуется Playwright и Chromium либо LLMS_BROWSER с путём браузера) проверяет интерфейс с имитацией API: редактирование, карточки, предпросмотр, сохранение и мобильную ширину. Это не интеграционный тест MODX. Снимок тестового интерфейса: `docs/admin-preview.png`.

Сборка и интеграционные проверки требуют работающего MODX 3 с базой данных. До релиза проверить установку, повторную установку, обновление и удаление пакета; HTTP Content-Type; несколько контекстов; ACL; даты публикации; отсутствие утечек под администратором и анонимным пользователем.

## Версия 0.6.0-alpha

Диагностика проверяет конфликт файла или ресурса `llms.txt`, PHP 8.1+, DOM, mbstring и возможность записи журнала. Установщик проверяет MODX 3, PHP 8.1+, DOM, JSON и mbstring. Проверить правила Apache/nginx программно из MODX нельзя: после установки откройте публичный `/llms.txt`.

В автоматических Markdown-карточках доступны выбранные TV и поля miniShop3 `price`, `old_price`, `article`, `weight`, `vendor`, `made_in`. Укажите имена через запятую в интерфейсе. Поля miniShop3 берутся из `msProductData`, если miniShop3 установлен. HTML-контент конвертируется в заголовки, абзацы, списки, выделение и ссылки Markdown без выполнения сниппетов.

Для сторонних ограничений добавлено событие `OnLLMSForgeResourceCheck`. Плагин интегратора получает `resource` и `context` и может вернуть `exclude`, чтобы скрыть ресурс из экспорта. Базовые проверки опубликованности, сроков и групп ресурсов остаются обязательными.

Добавлены русские и английские лексиконы названий настроек. Для английской культуры MODX добавлен перевод основных элементов интерфейса; некоторые пояснения и серверные ошибки ещё выводятся по-русски.

Проверено на тестовом `moysklad.dev23.ru`: transport-пакет собрался на MODX 3 / PHP 8.3, установился и повторно установился; `/llms.txt` отдал `200 text/plain`, неизвестная карточка — `404`, тестовый запрос `GPTBot/1.0` появился в журнале. Версия `0.6.2-alpha` также установилась, событие `OnLLMSForgeResourceCheck` создано. Резервная копия прежних файлов сохранена на тестовом сервере. Отдельно ещё требуется проверить удаление на чистой тестовой установке, права доступа и полностью перевести сообщения интерфейса. Версия `0.6.2-alpha` остаётся предварительной.
